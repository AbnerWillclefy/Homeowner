# Backend rules

These rules come from findings the reviewer raised in more than one pull request (`.claude/skills/review-lessons/`).

- Give each new branch its own test case, usually a table row: both ends of an accepted range, every rejected input (an extra key, a wrong type, a value over a limit) and every row a loop skips. A branch you add to answer a review finding gets its test in the same push. Why: an untested branch was the most frequent backend finding (#451, #463, #500, #501, #502, #506, #511, #514), and still was (#761, #765, #766, #789, #815, #818).
- When you change which month a card charge or card bill counts in, add a table row for each edge: a charge on the closing day, one dated after today, a card whose due day comes before its closing day, a card with no typed days, and a bill the bank reported closed. Why: each of these was counted in no month or in two (#677, #694, #697, #728).
- In `internal/finance`, log a database or provider error only through `safeErr`, never `err.Error()`. Why: a database error can quote a row, so the raw text leaks a Resident's data into the logs (#674).
- Before pushing a new migration, fetch `main`, number the file after its newest one and set `latestMigration` in `db_test.go` to match. Why: two migrations built in parallel took the same slot, and the one merged out of order blocked every later migration on staging (#727).
- When you look up a row by an id or a month offset another query gave you, check the map's `ok` or the slice's bounds and skip or refuse on a miss: a missing key must not read as the zero value or index past the end. Why: a purchase went to item 0, a card bill to the wrong card, and a far due date panicked (#764, #766, #806).
- When two writes must not interleave (a Restriction and a responsible Resident, a Chore edit), both lock the shared row with `SELECT ... FOR UPDATE` first, in the same order. A conditional `UPDATE ... WHERE` does not wait on a row lock when the committed row fails its `WHERE`, so it silently skips the row. Why: a restricted Resident could stay responsible for a Chore, the state ADR 0004's referee forbids (#752).
